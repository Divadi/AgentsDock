伺服器參考

一臺機器上的多個伺服器

一臺機器、一個使用者帳號、多個完全獨立的 AgentsServer——各自擁有自己的連接埠、服務、token、對話歷史和終端機。適合分開工作與個人用途、在穩定版旁邊跑一個測試版，或給每個專案一個專屬伺服器。

可用性

AgentsServer 1.0.9 及之後版本已支援。先安裝預設伺服器，再使用 agentsdock new 建立額外的命名服務。初始 npm 安裝只建立預設服務。

執行個體如何工作

你的第一個伺服器是預設執行個體——它保留你現有的路徑、服務名和連接埠。每個額外的伺服器都是一個命名執行個體（work、beta……），擁有自己的服務、連接埠、設定、狀態目錄、日誌和 tmux 服務，以預設執行個體的同級身份安裝。它們之間不共享任何東西，移除預設執行個體也絕不會移除命名執行個體。

執行個體是為方便而設的獨立服務——它們之間不是安全邊界，因為都以你的使用者帳號執行。

建立執行個體

在伺服器機器上執行：

# automatic name and the next free port (7851 upwards)
agentsdock new

# or choose the name and port
agentsdock new work --port 7851

# optional bind address (default 0.0.0.0)
agentsdock new lab --port 7852 --bind 0.0.0.0

新執行個體從空的對話清單開始，並擁有自己新產生的 token。名稱須為小寫：一個字母開頭，後接最多 31 個字母、數字或連字元。

建立命名執行個體時，輸出大概會像這樣：

$ agentsdock new work --port 7851
Create: work:7851
[7/7] AgentsServer 1.0.10 is ready

  Server URL    http://100.100.100.12:7851

AGENTSDOCK_SETUP_RESULT={"server_url":"http://100.100.100.12:7851","access_token":"ad_tok_...","service":"launchd","tailscale_ip":"100.100.100.12","server_version":"1.0.10"}

列出並連線

agentsdock list        # name, status, port
agentsdock info work   # details for one instance

清單輸出範例：

NAME                 STATUS     PORT
default              running    7850
  Tailscale / other networks: http://100.100.100.12:7850 (recommended)
  Same Wi-Fi / LAN:          http://192.168.1.23:7850
  This machine only:         http://127.0.0.1:7850

work                 running    7851
  Tailscale / other networks: http://100.100.100.12:7851 (recommended)
  Same Wi-Fi / LAN:          http://192.168.1.23:7851
  This machine only:         http://127.0.0.1:7851

把應用程式連線到執行個體的方式和連線任何伺服器完全一樣——URL 是主機地址加該執行個體的連接埠，token 用這條指令獲取：

agentsdock token work

在應用程式裡新增多個執行個體，在伺服器切換器中隨時切換。

更新執行個體

每個執行個體獨立更新。請在應用程式裡對要更新的伺服器連線使用託管更新。初始 npm 安裝不建立也不更新命名執行個體。

每個執行個體的位置

把 NAME 替換為執行個體名。

  • 服務：agents-server-NAME（Linux，systemctl --user）· com.agentsdock.server.NAME（macOS LaunchAgent）
  • 狀態（對話、工作、檔案、token）：~/.agentsdock-instances/NAME
  • 設定：~/.config/agents-server-instances/NAME
  • 執行環境釋出：~/.local/share/agents-server-instances/NAME
  • 日誌：~/Library/Logs/AgentsServer-instances/NAME/（macOS）· journalctl --user -u agents-server-NAME（Linux）
  • 所有執行個體的登錄檔：~/.config/agents-server-manager/instances.json（只含名稱、狀態、連接埠——不含任何機密）

預設執行個體保留檔案位置中列出的標準路徑。

每個執行個體的終端機

每個命名執行個體的對話終端機都執行在它自己的 tmux 服務上，因此絕不會與預設伺服器的對話或你在 tmux 裡跑的其他東西混在一起：

tmux ls                             # default server's chat terminals (zd_*)
tmux -L agents-server-work ls       # the 'work' instance's terminals (zdi_work_*)

移除執行個體

agentsdock remove work                    # one instance
agentsdock remove --all                   # every instance, including default
agentsdock remove --all --exclude default # every named instance, keep default

移除會停止服務並刪除執行環境和設定（包括該執行個體的 token）；其對話歷史預設保留。當一個名稱被釋放時，它的狀態目錄會被移到私有備份，而不是抹除——見名稱釋放備份。--purge-state 是唯一的破壞性選項，且總是要求輸入完整路徑。

規則與限制

  • 預設執行個體不能被釋放；只有命名執行個體可以。
  • 移除預設伺服器絕不會影響命名執行個體（它們是同級根目錄，不是子目錄）。
  • 連接埠必須空閒且未被預留；管理器絕不會為了佔用連接埠而停止已有的監聽處理程序。
  • 匯入的服務供應商歷史在執行個體之間互斥，同一個 Claude/Codex 對話不會被採納兩次。
  • 執行個體共享你的使用者帳號，彼此之間不是沙箱。
