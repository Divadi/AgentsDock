管理伺服器

AgentsServer 是執行在你自己機器上的開源後端。下面的所有操作都在那臺機器的終端機裡完成——是伺服器，而不是執行應用程式的裝置。

GitHub 上的 AgentsServer →

想查全部安裝選項、環境變數、一臺機器上的多個伺服器或備份？請看伺服器參考。

全程不需要 sudo。安裝指令碼以你的使用者身份執行，保留上一個健康版本以便回滾，並在每次更新中保留你的對話歷史、工作、檔案和 token。

安裝與更新

安裝前：伺服器機器需執行 macOS（Apple 晶片）或 Linux，並安裝 Node.js 22.14 或更新版本、npm 和 uv。AgentsDock 不會自動安裝 uv。macOS 已安裝 Homebrew 時，執行 brew install uv；Linux 或其他安裝方式請見 uv 官方安裝指南。

在同一個終端機裡確認 uv --version 正常，再用將要執行伺服器的使用者安裝 AgentsDock CLI：

npm install -g agentsdock

在一臺新機器上，全域安裝會建立預設使用者級服務，並把執行環境安裝到 ~/.local/share/agents-server。標準安裝不需要 clone repo。不要使用 sudo。本機 npm install agentsdock 只會新增專案依賴，不會建立伺服器服務。

安裝後執行 agentsdock list，確認 default 正在執行並查看 URL，再用 agentsdock token default 查看 token。npm 可能隱藏安裝提示，詳細內容請見連線資訊輸出範例。

更新已有伺服器時，在應用程式裡操作：開啟設定 → 更新，點選 Check now，然後在出現時使用 Update server 或 Retry server update。託管更新會換上新的執行環境、重新啟動服務，並保留你的 token 和狀態。

自訂安裝選項

AGENTSDOCK_SKIP_SETUP=1 npm install -g agentsdock
agentsdock setup [--port PORT] [--bind ADDRESS] [--non-interactive] [--dry-run]
  • --port PORT——固定使用指定連接埠（預設 7850）。
  • --bind ADDRESS——繫結地址（預設 0.0.0.0，其他裝置可以存取）。
  • --non-interactive——不出現任何提示；用於指令碼化或透過 SSH 驅動的執行。
  • --dry-run——顯示實際會執行的原生安裝指令，但不執行。

在伺服器上安裝並登入你計畫使用的服務供應商 CLI。tmux 可選——它支撐應用程式內終端機和託管更新。如果安裝時顯示 PATH 中需要 uv，請見 uv 疑難排解。

如果舊伺服器在 1.0.4 遷移期間中斷，在伺服器機器上執行 agentsdock recover，然後回到應用程式裡選擇 Retry server update。

檢視你的 token

之後隨時想看 token，在伺服器上執行下面的指令——它唯讀取現有設定，不做任何更改：

agentsdock token default

命名伺服器請把 default 換成對應名稱。不帶名稱執行 agentsdock token，可以互動選擇伺服器。

新增伺服器時把它貼上到應用程式的token欄位（參見安裝與連線）。

確認正在執行

在伺服器機器上：

agentsdock status

它會顯示每個伺服器執行個體的狀態、地址、已安裝版本和連接埠。只看某個命名執行個體時，執行 agentsdock status NAME。在應用程式裡，設定頁顯示同樣的執行環境檢查，以及一個重新啟動伺服器（Restart server）按鈕。

輸出範例：

Server (default):
  Status:   running
  Address:  http://100.100.100.12:7850 (Tailscale / other networks)
            http://192.168.1.23:7850 (Same Wi-Fi / LAN)
            http://127.0.0.1:7850 (This machine only)
  Version:  1.0.10
  Port:     7850

啟動、停止與重新啟動

安裝指令碼會把 AgentsServer 註冊為登入時自動啟動的使用者級服務。日常服務控制直接使用 AgentsDock CLI：

# default server
agentsdock restart default
agentsdock stop default
agentsdock start default

# named instance
agentsdock restart work

日常檢查優先用 agentsdock status 或應用程式裡的設定頁；只有排解問題時才需要直接看日誌：

# macOS
tail -f ~/Library/Logs/AgentsServer/server.log
tail -f ~/Library/Logs/AgentsServer/server-error.log

# Linux
journalctl --user -u agents-server.service -f

解除安裝

agentsdock remove default

這會停止並移除服務、版本化的執行環境，以及包括 token 在內的產生設定。做任何更改前都會先詢問（--yes 跳過提示）。~/.agentsdock 下的對話、工作、檔案和終端機會保留，之後重新安裝會直接接管它們。

若要連同這些狀態一起刪除，加上 --purge-state——它總是要求你輸入完整路徑確認，且不可撤銷。持久對話終端機會作為 tmux 對話繼續留在這臺伺服器的 tmux 服務上；tmux ls 可以列出它們。只關閉你確認屬於本伺服器對話終端機的對話——機器上的其他 tmux 對話，以及任何命名伺服器執行個體（它們使用各自的 tmux socket），都不受解除安裝預設伺服器的影響。

設定與檔案位置

伺服器上各項內容的位置：

  • ~/.agentsdock——對話歷史、工作、檔案、token（狀態目錄）。
  • ~/.config/agents-server/env——產生的服務設定，包括 token。
  • ~/.local/share/agents-server/releases/<version>——版本化的伺服器釋出；~/.local/share/agents-server/current 指向目前生效的版本。
  • ~/Library/Logs/AgentsServer/（macOS）或 journalctl --user（Linux）——日誌。

大多數設定都是環境變數。你最可能用到的有：

  • AGENTSDOCK_AGENT_PORT / AGENTSDOCK_AGENT_BIND——連接埠（7850）和繫結地址（0.0.0.0）。
  • AGENTSDOCK_AGENT_TOKEN——共享的 token。
  • AGENTSDOCK_STATE_DIR——狀態目錄（~/.agentsdock）。
  • AGENTSDOCK_AGENT_CWD——新對話的預設工作目錄（你的主目錄）。
  • AGENTSDOCK_BACKEND——預設後端，claude 或 codex。
  • CLAUDE_BIN / CODEX_BIN——命令列工具不在 PATH 中時的可執行檔案路徑。

完整清單（包括工作並行和記憶體保護）見 server 原始碼樹。

保持私有。不要把 7850 連接埠暴露到公網。透過 Tailscale 或其他私有網路存取伺服器，並保持 token 啟用。
